# dsh-vibe-zhishi

给 DeepSeek Harness 的一个 **skill 插件**：把「一条内容为什么没人看完」变成能数的东西。

它不渲染视频，也不替你发。它管判断：**选题值不值得做、开头留不留得住人、发出去之后数据说了什么。**

## 这是什么

一套可以加载的规则，三部分：

- **选题卡**：五问，答不满就别开工（第一句是什么、主意象、反转、出处、自评）
- **开头三秒**：能数的硬指标（第一句 ≤ 12 字、8 秒内点题、零铺垫）
- **回读**：发出去两小时/二十四小时各读一次，用四个数判断是哪一步的问题

## 这不是什么

- **不是一键出片。** 渲染要 HyperFrames + ffmpeg，这个包不含，也不假装含。
- **不是爆款公式。** 里面的阈值来自小样本实测，当方向用，不当定律。
- **不替你决定发不发。**

## 为什么只做「判断」这一半

渲染那半在 DSH 的环境里不一定跑得动：HyperFrames 依赖 ffmpeg，字体和 Chrome 路径各平台不同，作者自己也写了「完整流程只在 macOS（M3 Pro）上跑过，其他系统没测过」。

而「开头为什么留不住人」这件事，**不需要渲染也能判断。**

先把判断做对，再谈生成。

## 装

```bash
dsh plugin --profile web add dsh-vibe-zhishi
```

本地开发：

```bash
dsh plugin --profile web add ./dsh-vibe-zhishi
```

装完新开一个会话，skill 目录里就会出现 `vibe-zhishi`。

## 用

```text
用 vibe-zhishi 给我这个选题做张选题卡：为什么"每况愈下"原本的意思正好相反
```

```text
这条发了，播放 23、文案展开率 3.57%、划走率 57.89%，帮我判断是哪一步的问题
```

```text
我这段开头帮我按「第一句 ≤ 12 字、8 秒点题、零铺垫」过一遍
```

## 里面有什么

```
.dsh/skills/vibe-zhishi/SKILL.md   ← 规则本体
cordis.patch.yml                   ← 加载配置
index.js                           ← 故意留空的插件入口（skill 走文件系统发现）
```

## 已知限制

- 阈值来自十三四条作品的实测（原作者）加一条（我）。**样本小。**
- 平台数据口径会变，展开率/完播率的定义各版本不同，用之前先确认。
- 这套只管「有没有人看完」，不管「看完有没有用」。后者只能靠人判断。
- Windows 上没做过完整测试；这个包不含任何平台相关的代码，但也没在别的系统上装过。
